 问题 1：搜索内容错误 - 根因分析

 症状

 data/firecrawl_search_responses/ 中记录的实际搜索查询：
 - "四川阿坝红旗大桥垮塌 2025年11月11日 西方媒体报道"
 - "西方主流媒体 四川阿坝 红旗大桥 垮塌 2025年11月11日 报道 反应"
 - "colapso \"Puente Hongqi\" Aba Sichuan 11 de noviembre 2025 cobertura medios occidentales reaccion"

 根本原因

 核心问题：系统将"用户意图词"错误地当作了"搜索关键词"

 用户查询包含两类词：
 1. 意图词（决定搜索哪些媒体，但不应该作为搜索关键词）：
   - "西方主流媒体"
   - "报道"
   - "反应"
 2. 事件关键词（实际应该用于搜索的词）：
   - "四川阿坝红旗大桥"
   - "垮塌"
   - "2025年11月11日"

 问题代码路径（src/services/langgraph_search/nodes/layer_search.py:309-315���：
 base_query = " ".join(keywords[:5])  # 最多使用 5 个关键词

 如果 state.keywords 包含了意图词，这些词就会被直接用作 base_query。

 问题 2：监督层如何工作

 LangGraph 监督机制概述

 监督层不是单一的"Supervisor"节点，而是通过 StateGraph 的条件路由实现分布式决策。

 关键决策点

 START → query_analyzer → source_discovery → [parallel layer_searches] → aggregator → validator → output → END

 各节点职责

 1. QueryAnalyzerNode (query_analyzer.py)
   - 使用 Claude LLM 分析查询
   - 提取：当事方、关键词、时间范围
   - 生成 4 层关键词组合配置
 2. SourceDiscoveryNode (source_discovery.py)
   - 动态发现官方信息来源
   - 返回 discovered_sources 用于后续搜索
 3. route_to_parallel_layers (条件路由函数)
   - 根据配置将任务并行分发到多个 LayerSearchNode
 4. LayerSearchNode (layer_search.py)
   - 执行各层级的实际搜索
   - 为每个层级构建优化的搜索查询
 5. AggregatorNode (aggregator.py)
   - 聚合各层级的搜索结果
 6. ValidatorNode (validator.py)
   - 验证结果质量（多源验证、权威验证等）
 7. OutputNode (output.py)
   - 格式化最终响应

 监督逻辑特点

 - 状态驱动：所有决策基于 SearchState 的状态流转
 - 条件路由：add_conditional_edges 实现智能分支
 - 并行协调：Send API 实现多节点并行执行
 - 质量监督链：aggregator → validator → output

 4层组合法的目标

 根据 query_analyzer.py:184-304 的提示词设计：

 - 组合1 (general_news): 省份 + 事件类型 + 完整时间
   - "Sichuan bridge collapse November 2025"
 - 组合2 (precise_location): 国家 + 地区 + 事件类型 + 实体名
   - "China Aba bridge collapse Hongqi"
 - 组合3 (entity_focused): 完整实体名 + 省份 + 年份
   - "Hongqi Bridge Sichuan 2025"
 - 组合4 (geopolitical): 民族地区名 + 事件类型 + 年份
   - "Aba bridge collapse 2025" 或 "Tibet bridge collapse 2025"

 总结

 1. 搜索内容错误的根本原因：用户意图词（"西方媒体"、"报道"、"反应"）被错误地当作搜索关键词
 2. 监督层工作方式：基于 StateGraph 的分布式条件路由，非集中式 Supervisor 节点
 3. 搜索任务的关键词拆分：系统当前拆分不正确，包含了意图词；正确拆分应只包含事件相关词
